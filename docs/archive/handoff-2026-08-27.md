## 4. Technical Context for the Codex Epic

The codebase is agent-agnostic by design (ADR-010 modular split + Strategy pattern).

- **Adapter interface**: `scripts/adapters/agent_adapters/base.py`
  - `AgentAdapter` base: `kind`, `blocked_markers`, `parse_permission_request`,
    `inject_approval` (returns `(approved, reason)`; `INJECT_SKIP_CHANGED` sentinel).
  - `@register` decorator + `get_adapter(kind)` + `target_agent_kinds()`.
- **Existing adapters**: `agy.py`, `opencode.py` (reference implementations).
- **To add Codex**: create `codex.py` implementing `AgentAdapter` with `kind="codex"`,
  `@register`. **No changes to `schengen_watcher.py`** (Open/Closed Principle — the
  docstring in `base.py` states this explicitly).
- **Data flow**: `schengen_watcher.py` polls panes → adapter `parse_permission_request`
  → decision layer → `pending_escalations` (`agent_kind` field) → TUI/LLM
  (`tools/schengen_agent_llm.py` `execute_tool_call` approve/reject) → adapter
  `inject_approval` keystrokes.
- **New this session** (relevant to any agent kind):
  - `pending_escalations.resolution` (APPROVED/REJECTED/UNANSWERED) set by
    `record_adjudication` / `cleanup_escalations` (`core/guard_db.py`).
  - `guard_config.answer_language` (default korean); herdr-injected
    `english_feedback` stays English regardless of answer language.
  - `get_recent_audit_logs` LEFT-JOINs `resolution`; `get_escalation_resolution`,
    `get_adjudications_for_audit`, `get_audit_log_by_id` helpers.
