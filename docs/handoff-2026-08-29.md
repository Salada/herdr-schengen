## 4. Technical Context (permission.reply / codex)

**OpenCode permission.reply pipeline (PR #95 + #105 + #109):**
1. Plugin `event` hook → `permission.asked` → writes per-pane JSON to
   `~/.local/state/herdr-schengen/opencode_permissions/<pane>.json` + tracks `permission_id`.
2. Watcher `get_pending_request` reads the channel (stage-gated) as the clean command source
   (pane-text is the fallback).
3. `channel_approve` (gated by `SCHENGEN_CHANNEL_APPROVE=1`) writes a decision to
   `opencode_decisions/<pane>.json`; the plugin polls it (1s) and replies via
   `client.postSessionIdPermissionsPermissionId({ path:{id,permissionID}, body:{response} })`.
   **Note**: the plugin `client` is the v1 flat SDK client — `client.permission.X` does NOT
   exist (PR #109 fixed this).

**Codex adapter (`scripts/adapters/agent_adapters/codex.py`):**
- Approval is a ratatui list modal: title `Would you like to run the following command?`,
  `$ <command>`, options `› 1. Yes, proceed (y)` …, footer `Press enter to confirm or esc to cancel`.
- Approve key = `y` (selection-independent); deny = `n`/`Esc`. `Ctrl+A` = fullscreen pager.
- `parse_permission_request` handles exec/network/edit/stdin/permissions; verified live for exec.
- **No "interview" dialog exists in codex** (searched). Other dialogs: trust-directory
  (startup), onboarding wizard (Welcome/Auth/Trust), plan-review (`Implement this plan?`),
  full-access confirmation (`Enable full access?` — requires explicit Enter), `/model`,
  `/permissions`, `/feedback`, slash-command popup, resume picker.
